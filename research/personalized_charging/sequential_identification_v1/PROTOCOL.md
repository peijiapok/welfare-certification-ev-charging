# Prospective protocol: sequential identification in a charging toy model

Status: FROZEN before the held-out scientific run; its source and this protocol are hashed in freeze_manifest.json. No historical experiment is reopened. This is an exploratory, simulation-only study, not evidence of field effectiveness and not a claim that this simple model represents a deployed site.

## Model and estimands

The process uses a single port and three half-hour slots; two requests have immediate default slots 0 and 1, respectively. Either can be offered slot 2 as an alternative; a confirmed first-offer reservation prevents a later offer of the same slot. An independent urgent unit demand arrives at slot 2 with probability 1/200, and is unmet if the slot is occupied. A persistent simulated driver's choice probabilities are p=sigmoid((0.1-theta)/tau) and r=sigmoid((0.1-theta/2)/tau), for theta in [0,0.25] and tau in [0.05,0.4]. The candidate first offers p and, if that fails, offers r; the baseline defaults both. Prices, procurement costs, objective and feasible actions match the published code and the previously checked P3c construction. For correct response probabilities the expected candidate advantage in credits is B=p(0.07-theta)+(1-p)r(0.05-theta/2). Its expected unmet is U=[p+(1-p)r]/200, and the default baseline has U=0. Collection and evaluation episodes reset only after all commitments end.

For the correct model, p>2/3 implies theta<1/15, which implies B>161/41100. A prior-uniform service bound U<=1/200 is used. This is a sufficient condition, not an exact equivalence: many beneficial models cannot be certified by this condition. Fixed probability 22/25 defines an alternative predictive distribution. The exact-rational rule rejects p<=2/3 the first time its likelihood divided by the supremum likelihood over p<=2/3 strictly exceeds 20. Predictable p probes enter this process; r responses are ignored. Adaptive skipping and stopping are allowed. Under the declared conditional Bernoulli model, false rejection of p<=2/3 at any time is at most 0.05. Since the service bound is deterministic, the benefit and service claims hold together under the stated assumptions; service is expected, not pathwise. These guarantees are per simulated driver, not familywise across all drivers. A deployment certificate additionally requires epsilon >= 1/200; otherwise the gate abstains.

## Catalog and resources

Six distinct labeled groups, 300 independent persistent drivers each, using NumPy PCG64 and master seed 730411. Each theta and tau is independently uniform on the indicated closed interval (endpoints occur with probability zero). Group order and draws are defined by the runner, frozen before generation:

1. easy: theta in [0,0.02], tau in [0.05,0.08], epsilon=0.005.
2. low-information positive: theta in [0,0.035], tau in [0.2,0.4], epsilon=0.005.
3. boundary: theta in [0.055,0.10], tau in [0.05,0.25], epsilon=0.005.
4. harmful: theta in [0.11,0.25], tau in [0.05,0.4], epsilon=0.005.
5. tight service: theta in [0,0.10], tau in [0.05,0.2], epsilon=0.0045.
6. misspecified: theta in [0.11,0.20], tau in [0.05,0.2], epsilon=0.005; actual p and r add +2 to their logistic logits, while the controller continues to assume the nominal model. This is explicitly outside the coverage guarantee. Evaluate actual advantage and actual U using actual response probabilities and the same specified welfare model.

Each collector has at most 64 reset collection episodes, and 32 subsequent reset deployment episodes, independently of other drivers. The observation rule is predictable: choose an offer using only earlier responses; offer p or r in each episode and update afterward. Collection service allowance is 1/200 expected unmet per episode, and 64/200 for the full collection horizon. Report actual collection cost and unmet separately and in a 96-episode lifecycle comparison against always-default. Each arm receives common exogenous draws indexed by driver, episode and event type, including separate p, r and urgent uniforms. Different opportunities are distinct random inputs; arms that expose the same opportunity share it. Evaluation innovations are disjoint from collection innovations. Default creates no response label.

Collectors: (a) p-only; (b) alternating p then r; (c) information-directed, maximizing the expected one-step reduction in posterior entropy of the sign of B on the declared fixed theta/tau grid; (d) capacity-aware myopic, maximizing posterior expected one-episode p or r collection benefit, including the expected urgent cost and delay cost. Break ties in favor of p. The finite grid contains 31 equally spaced theta values from 0 to 0.25 and 15 equally spaced tau values from 0.05 to 0.4, with equal initial weights. It is used solely by the collection heuristics and the plug-in comparator, not for the exact certificate. All collection policies use the same 64-episode cap and same physical opportunities. All decisions are evaluated on each collector's identical data: the exact anytime gate and an ungated grid-posterior plug-in rule that deploys when posterior mean B>0 and posterior mean U<=epsilon. The plug-in is a decision comparator and does not claim anytime error control. A no-data default arm provides a lifecycle reference. A known-model oracle is a non-deployable 32-episode deployment-only reference; it is not a full 96-episode lifecycle upper bound, because the collectors can accrue gains or losses during collection. Compare it only against deployment outcomes. If early gate stopping is logged, all collection still runs to the common horizon, so analysis does not silently grant one method fewer collection costs.

Primary descriptive quantities, by group and method: ever-certified/deployed fraction, false-certification fraction among all driver/world units whose true B<=0 or true U>epsilon, separate diagnostics for declared B>161/41100 and nominal p>2/3, abstention fraction, mean actual net lifecycle benefit over default, expected deployment service, realized collection and evaluation unmet service, collection samples and first-crossing time, expected collection unmet under the actual response law, and paired per-driver differences. Estimate proportions with Wilson intervals and paired mean differences with 2,000 paired-bootstrap resamples using PCG64 seed 730412 over independent drivers (not episodes); intervals are descriptive and not multiplicity-adjusted. Sample counts and denominators must be reported, especially for conditional false-certification rates. Nothing is declared superior solely from an unadjusted interval. Report total compute time and resource usage. The fixed budget is a 600-second elapsed wall-clock cap for the scientific run, checked cooperatively at driver boundaries and after analysis, one attempt, with failure reporting and no retuning on held-out results. One driver, summary or final output write may overrun the cap. A started sentinel identifies a missing completion receipt as incomplete; uncatchable termination cannot write a final receipt. A partial or interrupted run is not to be silently extended; it is an incomplete result.

## Validity checks and limitations

Before any held-out evaluation: deterministic physical transition tests, distinct-event innovation and true-parameter isolation checks, exact likelihood tests, arithmetic agreement, no-offer/no-feedback check, helpful and harmful parameter controls, strict-service abstention and reproducibility checks. Keep scientific generator parameters and runtime code independent of dev-only review notes. Hash source, protocol, environment and results. On any test failure, repair before freeze and document; do not inspect held-out results to choose fixes.

The study is deliberately small: one shared port and one persistent modeled driver with two vehicles; costs, arrivals, stochastic independence and the logistic welfare link are assumptions. It does not establish general multi-driver validity, realistic adoption, RL improvement, exact robust optimization performance or publication readiness. A grid-based comparator is not a rigorously certified continuous-domain generic solver. Related comparisons and a broader scenario suite remain necessary for stronger claims.
